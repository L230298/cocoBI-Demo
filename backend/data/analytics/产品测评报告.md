## 6. 核心问题分析

> 基于 4 条 BadCase + 错误统计，归纳当前产品的 5 大核心问题：

1. **业务术语映射能力缺失**（最严重）—— PRD §3.3.2 规范了 `query_business_glossary` 工具但未实现，导致 SchemaAgent 无法识别"库存/客单价/复购率"等业务词。Q05 直接被映射到 orders 表的 category 字段，**答非所问严重伤害用户信任**。这是 NL2SQL 类问题的最高频根因。

2. **意图枚举边界未受约束** —— IntentAgent 的 Prompt 未限定输出枚举，导致输出 PRD §3.1.4 未定义的 `QueryTrend`。这暴露两个潜在风险：① 后续如果有 6+ 个未知意图，StorytellingAgent 不知道怎么处理；② 评测和监控指标无法对齐（5 个意图是 PRD 约定的边界）。

3. **前端输入校验缺失**（已修复） —— Q09 空字符串直达后端，被 FastAPI 拒绝抛 422。前端 Textarea 应该有 min_length=1 的友好提示，而不是让用户看到技术性错误。已通过 commit `1209815` 修复。

4. **I5 上下文复用逻辑缺失** —— PRD §3.1.4.5 明确要求 I5 复用前置意图的数据，但当前实现每次都触发新查询。这在单次查询场景下无感，但在多轮对话场景下会让用户觉得"你为什么又查了一次"。

5. **轻量闭环边界未校验** —— Q08 Chitchat 命中后仍走完 StorytellingAgent 流程，输出 next_steps / followups，但语义上 Chitchat 不应该输出"下一步建议"。当前实现没拦截。

## 7. 产品迭代建议

按优先级排列（每条包含 问题 / 改法 / 验收标准 / 下一轮测评重点）：

### 🔴 P0-1：业务术语库 + Schema 映射升级
- **问题**：BC-002（库存查询答订单分类）
- **改法**：补 `query_business_glossary` 工具；初始化 GMV/客单价/复购率/库存等首批术语；SchemaAgent Prompt 增加"业务术语优先"规则
- **验收**：评测集 `evaluation/schema_mapping/` 通过率 ≥ 90%；术语识别覆盖率 ≥ 80%
- **测评**：回归 BC-002；新增 20 条业务术语 query

### 🔴 P0-2：意图枚举边界校验
- **问题**：BC-003（QueryTrend 越界）
- **改法**：IntentAgent Prompt 限定输出 5 个核心意图 + Unknown；Python 层做枚举校验；PRD §3.1.4.6 显式声明
- **验收**：100 条 query 中 intent 字段只出现 5 个 + Unknown
- **测评**：回归 BC-003；新增 30 条边界 query

### 🟡 P1（已修）：前端输入校验
- **状态**：✅ commit `1209815` Q09 422 处理器已上线

### 🟡 P1（新增）：评测集分级管理
- **问题**：当前评测仅 10 条手工 query，PRD §3.6.3 要求分级评测集
- **改法**：建立 `evaluation/{intent,nl2sql,attribution,interpretation,by_industry}/` 目录，按周/月/版本回归
- **验收**：评测集 ≥ 200 条；每意图覆盖 easy/medium/hard/edge 四档

### 🟢 P2-1：I5 上下文复用
- **问题**：BC-004
- **改法**：Orchestrator 识别 I5 时从 conversation_history 复用前序 query_id；无前序时用"最近 7 天"默认值兜底
- **验收**：多轮 I5 不产生新 query_submitted 事件

### 🟢 P2-2：轻量闭环边界校验
- **问题**：Q08 Chitchat 输出 next_steps
- **改法**：intent=Chitchat 时跳过 StorytellingAgent
- **验收**：Chitchat query 的 next_steps_count=0 且 followups_count=0

## 9. 测评结论

### 当前是否可用？

**可用，但 P0 缺陷必须修复后才能上线。**

5 个核心意图均能跑通完整 4-Agent 流水线（10 个 query 中 9 个完成），SQL 执行成功率 100%，轻量闭环元素（next_steps + followups）均能生成。但：

- ⚠️ **业务术语映射缺失**导致"问库存答订单"——严重失真，影响产品核心价值
- ⚠️ **意图越界**暴露了 Prompt 边界约束的不足，未来扩展时风险大
- ✅ **错误率**已通过前端校验修复
- 🟢 **I5 上下文复用**和 **Chitchat 轻量闭环校验**是体验优化项，不阻塞上线

### 主要风险

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 用户首次查询"库存/客单价"等业务词即失真 | 🔴 高 | P0-1（业务术语库）|
| IntentAgent 输出不可控意图名 | 🟡 中 | P0-2（枚举校验）|
| 多轮对话体验下降 | 🟢 低 | P2-1（I5 上下文）|

### 下一步优化方向

1. **优先**：实施 P0-1（业务术语库 + Schema 映射升级）和 P0-2（意图枚举边界校验）
2. **次优**：建立 200+ 条分级评测集（PRD §3.6.3）
3. **持续**：线上 demo 已支持 `events.jsonl` 埋点下载（commit `3ee32a7`），可按周回归
